# 用户模型分层，以及每个会话只完整送一次说明

- **状态**：待讨论，等出现瓶颈再做
- **提出**：2026-11-13
- **涉及**：进化模块规范 §5、§6、附录 A；基础规范 §4、§5.2、§5.3、§10

## 背景

现在 `LEARNED.md` 限制在 1500 字以内，每次请 Agent 预测时，都会跟在 `PREDICT.md` 的说明后面一起送过去。用户希望用户模型能写得更详细，讨论过程中发现两件事：

1. **把字数限制放宽到 15000 字，每轮的开销会变大。** 15000 个中文字大约是 1.5 万到 2 万个 token，每次预测都要附上一份。
2. **附上的内容会在对话记录里越积越多。** 在 Grok、Claude Code 这类环境里，拦下一轮时附上的说明会作为一条消息留在对话记录中。每轮附一份，对话里就多一份。按 15000 字算，十来轮就是 20 万 token，Grok 的上下文上限是 256K。现在的设计也有这个问题，只是量小：每轮约 1.6K 字的说明，加上最多 1500 字的心得，不到 1K token。

**结论（2026-11-13）**：先按 1500 字继续用，看到下面的瓶颈信号再分层。理由是现在还没有任何真实记录，不能证明分层有用；这个设计以后再加也不难，记录格式不受影响。

## 什么时候算到了瓶颈

满足任意一条就该做：

- 学习时 Agent 说，有证据充分的规律因为字数限制放不下；或者心得每次都写到接近 1500 字。
- 长会话里上下文压缩变得频繁，而且能看出是 Sibyl 反复附上的说明占了大头。
- `/predict stats` 显示学习前后命中率不再提升，而心得已经写满。

## 方案 A：用户模型分两层

| | 摘要 | 全文 |
|---|---|---|
| 位置 | `LEARNED.md` 开头的 `## Summary` 一节（也认 `## 摘要`） | 同一个文件的其余部分 |
| 长度 | 不超过 2000 字（硬性） | 不设硬性上限；建议控制在 5 万字以内，超过时学习必须合并、删减 |
| 什么时候送给模型 | 随完整说明一起送（见方案 B） | 不主动送，Agent 需要时自己读，附上的说明里写明路径 |
| 内容 | 最有用的几条规律和校准数字 | 全部规律、例子、按项目的细节，按主题和项目分节 |
| 学习时怎么改 | 每次学习都重新提炼 | 按小节就地修改，不整份重写 |

外壳不变：开头一行版本信息；每条规律带证据次数；少于 3 次的不写；校准数字照抄统计结果；不写凭据和个人身份信息。另外加两条：

- 每条规律带上最后一次见到的日期，例如 `(22/30, 2026-11)`。很久没再出现的、被新记录推翻的，学习时删掉，文件就不会只增不减。
- 引用用户原话只用短例子，不大段照抄。全文越长，存下的原话越多。

## 方案 B：每个会话只完整送一次说明

- **只在一种环境里用简短版**：环境会把拦下时附上的说明留在对话记录里，比如 Grok、Claude Code。这由接入代码告诉核心，作为一个新输入 `keepsReasons`，默认为否，也就是每次都完整送。
- **完整送一次之后**，后面几轮只附一行：
  ```
  [Sibyl] mode=suggest may_act=no
  Predict as the Sibyl instructions given earlier in this conversation say.
  ```
- **以下情况重新完整送一次**：
  - 说明内容变了：`PREDICT.md` 的正文或心得摘要变了。用二者的哈希作为 `briefKey` 来判断，取 SHA-256 的前 16 位十六进制，各语言实现结果一致；
  - 上下文被压缩了：接入代码能判断时传入 `event.contextReset`，比如 Grok 有压缩前后的 hook；
  - 已经连续送了 9 次简短版：第 10 次重新完整送，作为兜底；
  - 用 `/predict on` 或 `off` 切换过开关。
- **核心的变化**：
  - `decide` 新增输入 `keepsReasons`、`event.contextReset`、`extra`（模块要附上的内容，比如心得摘要）；
  - 新增输出 `brief: "full" | "short"`；
  - 状态里新增 `brief`（自上次完整送出后的次数）和 `briefKey`。
- **进化模块**：心得摘要作为 `extra` 交给核心，只在完整送出时附上，不再每轮都附。

方案 B 对没装进化模块的人同样有用：`PREDICT.md` 的说明也不会每轮重复。

## 要改的地方

  - §6 改写成两层结构；
  - 附录 A 的学习说明写明两层、就地修改、日期和 5 万字的软上限；

- **已安装的环境**：Grok 需要按新规范再升级一次。

## 代价和风险

- 基础核心和模块都会变复杂，所有已安装的环境都要升级。
- 简短版的前提是之前那份完整说明还在对话记录里。如果环境压缩了上下文、却没有办法通知接入代码，就只能靠「每 10 次重新完整送一次」兜底，中间几轮 Agent 可能找不到说明。
- 全文的读取要靠 Agent 自觉，它可能不读，也可能读太多。

## 待定

1. 三个数字：摘要 2000 字、全文软上限 5 万字、每 10 次重新完整送一次，合适吗？
2. 摘要一节的标题用英文 `## Summary`，同时认中文 `## 摘要`，可以吗？
3. 方案 A 和 B 可以分开做。如果只遇到上下文压缩的问题，可以先只做 B；如果只是写不下，可以先只做 A。
