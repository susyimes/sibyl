# Sibyl

![Sibyl：女预言者望向聊天窗口里的三条建议](assets/sibyl.png)

让你的 Agent 在每轮结束时，替你预测下一句要说什么。

> Sibyl（西比尔）是古希腊传说里的女预言者。

> **现状**：
> - **基础功能**：Grok CLI 已经照规范给自己装上，并在真实对话里通过了全部验收。
> - **[进化模块](#进化模块可选)**：Grok CLI 也已经照规范装上，并在真实对话里通过了全部验收。

## 它做什么

Agent 每干完一轮，就站在你的角度想想你接下来最可能说什么，然后在原来的对话里列出来：

```
Sibyl: 你可能想说
s1. 跑一下测试 · 0.60
s2. 顺便把 README 也更新一下 · 0.20
s3. 提交并推送到 main · 0.10
```

- **回 `s1`**，就等于说了那句话；后面还可以接着补充，比如 `s2 顺便把测试也跑了`。
- **建议用 `s1`、`s2`、`s3` 编号**，不占用纯数字。Agent 自己的回答里列了 1、2、3 个方案时，你回纯数字 `2` 仍然是选它的方案 2，两套编号不会冲突。这种时候，Sibyl 会预测你会怎么选，比如 `s1. 选 2，按你推荐的来 · 0.55`，而不是把方案重复一遍。
- **每条后面的数值是确定性**：Agent 认为你下一句就是这句的概率，取 0 到 1，保留两位小数。几条加起来不必凑满 1，差的部分就是「其他可能」。

打开 `act` 模式后，像「跑一下测试」这种只是接着当前工作往下走的一步，它会自己接着做，默认最多连做 3 步，并先写一行 `Sibyl: “跑一下测试” · 0.85` 说明它预测的是哪句、有多大把握。推送、发布、删除、花钱、碰凭据，或者需要你选方向的事，它只列出来，不替你做。

## 它怎么做到的

预测由 Agent 自己来做：同一个 Agent，同一段上下文，用上它已经知道的一切，包括这段对话、手头工作的进展，以及你在指令文件和记忆里留下的习惯。Sibyl 只在外面加三样东西：

- **一个结束时的触发**：一轮结束时，如果这个会话开着 Sibyl，就先不让这一轮结束，把 `PREDICT.md` 的正文交给 Agent，请它预测完再结束。这一步不调任何模型，也不联网。
- **`/predict` 命令**：按会话开关。
- **`PREDICT.md`**：头部写配置，正文写给 Agent 的说明。

规范不点名任何工具。它只描述 Sibyl 需要环境提供的四种能力：
1. 一轮结束时能让 Agent 接着干的机制；
2. 按会话保存的状态；
3. 放 `PREDICT.md` 的地方；
4. 接收 `/predict` 的通道。

在你的环境里这四样分别是什么，由安装它的 Agent 自己去找。本机的命令行工具、云端的 Agent、架构未知的 Agent 都一样。

- 能找到第 1 种能力，就是 **L2**：每轮结束都会可靠触发。
- 找不到，就退到 **L1**：把说明写进 Agent 常驻的指令里，效果靠它自觉。

## 安装

对你的 Agent 说一句：

> Install Sibyl for yourself according to https://github.com/susyimes/sibyl/blob/main/SPEC.md

它会做这些事：

1. 先查清自己的环境能提供什么，告诉你能装到哪一档；
2. 用参考核心，或者把它移植成自己环境的语言；
3. 把它接到自己的结束机制上，再装好命令和默认的 `PREDICT.md`。原有的配置只合并、不替换，所有改动都会记下来，方便撤销。需要你批准或信任的地方，它会停下来请你来做。

**验收**，三条都满足才算装好：
1. 核心通过 `conformance/cases.jsonl` 的全部用例。
2. 在真实环境里实际看到四件事：
   - 关着时正常结束，对话里看不到 Sibyl 的任何痕迹，状态存储也没被改动；
   - `/predict on` 之后，下一轮以 `Sibyl:` 建议块结尾；
   - 你再发一条消息，计数重新开始；
   - 状态存不了的时候，这一轮照样正常结束。
3. 停用和重新启用：`/predict disable` 之后，改过的配置文件和安装前的备份逐字一致，Agent 的表现和安装前一样；再说一遍安装那句话，又能用了。

装不上时，它会撤销改动，并告诉你卡在哪一步、现在还能用哪一档、要装到 L2 还缺什么。

## 使用

| 命令 | 作用 |
|---|---|
| `/predict on` | 在当前会话开启（默认 `suggest`：只列出预测） |
| `/predict on act` | 开启，并允许它自己接着做明显的下一步 |
| `/predict off` | 在当前会话关闭 |
| `/predict status` | 查看档位、生效的 `PREDICT.md` 和开着的会话 |
| `/predict disable` | 在这个 Agent 上全局停用：把 Sibyl 从它的配置里整个撤出去，不影响别的 Agent |
| `/predict uninstall` | 停用，并删掉这个 Agent 的安装文件；你的设置和记录这类共用文件会保留 |

**装好后默认开启，用 suggest 模式。** 以后每个由你直接操作的会话，结尾都会出建议，不用再输入 `/predict on`。`act` 模式只有你自己要求才会开。
- **由脚本或别的程序启动的会话默认关闭**，比如一次性的 `grok -p` 调用：没人会回它的建议，多出一段内容还可能弄坏读取输出的程序。
- **想让某个脚本完全不受影响**：给它设上环境变量 `SIBYL=off`。
- **想改回默认关闭**：在 `PREDICT.md` 里写 `default_on: false`。
- **只关某一个会话**：`/predict off`。`on` / `off` 只影响你输入命令的那个会话。

**关闭时完全不起作用**，分两档：

- **`/predict off`**：只关当前会话。每轮结束时还会做一次很快的开关检查，但不往模型里送任何东西，不输出，也不写文件，对话和没装时一样。（L1 例外：那段说明每轮都会被读到，要完全不起作用得用 `disable`。）
- **`/predict disable`**：全局停用。撤掉 Sibyl 在 Agent 配置里的全部登记，改过的配置文件恢复成安装前的样子。Sibyl 自己的文件和改动记录留在它自己的目录里，不起作用。想重新启用，把安装那句话再说一遍就行：它会根据改动记录把登记加回去，不用重装。

## 配置：`PREDICT.md`

Sibyl 按以下顺序取第一个存在的：
1. 项目级的 `PREDICT.md`；
2. 用户级的 `PREDICT.md`；
3. 内置默认，也就是 [PREDICT.md](PREDICT.md) 这份。

改完下一轮就生效。想让每次预测都知道、又不想被学习改掉的事，比如「我说『推』就是推到 main」，写在这份文件的正文里。

```markdown
---
default_on: true      # 由你直接操作的新会话是否默认开启（脚本启动的会话总是关闭）
mode: suggest         # suggest：只列出 | act：明显的下一步可以自己接着做
max_auto_turns: 3     # act 模式下最多连做几步，到了就停下来列出建议
---
（给 Agent 的说明：怎么预测、什么情况只列出不做……）
```

## 多个 Agent 共用 `~/.sibyl`

同一台机器上，你给几个 Agent 装 Sibyl，它们就共用同一个目录，你的设置、各会话的开关、记录和用户模型都会跟着你换 Agent：

```
~/.sibyl/
  sibyl.json           登记了哪些 Agent 装了 Sibyl
  PREDICT.md           你的设置和长期备注                  共用
  sessions/            各会话的开关和计数                  共用
  journal.jsonl        进化模块的记录                      共用
  LEARNED.md           进化模块学到的用户模型              共用
  agents/<名字>/       某一个 Agent 自己的安装：接入代码、核心副本、改动记录
```

**安装时目录已经存在，分四种情况处理：**

| 情况 | 处理 |
|---|---|
| 有 `sibyl.json` | 别的 Agent 已经装过。把自己登记进去，你的设置和记录原样沿用；如果自己装过，就改为重新启用或升级 |
| 有 Sibyl 的文件，但没有 `sibyl.json`（早先的安装把文件放在了根目录） | 补写 `sibyl.json`，把早先的安装登记成「就在原处」。不搬动它的文件，因为它的登记指向那里；装完告诉你 |
| 是个不相干的同名目录 | 一个字都不动，停下来问你换个位置 |
| 你的 `PREDICT.md` 和当前默认版本不同 | 保留你的。如果当前默认版本里有你缺的重要内容（比如新的输出格式），告诉你，由你决定要不要加 |

还有一种情况要防：有的工具会顺带执行别家工具配置里的 hook（比如 Grok 会读 Claude Code 的设置）。两家都装时，同一轮可能被拦下两次，所以安装的 Agent 要先检查，不重复登记。

停用和卸载只影响执行命令的那个 Agent；只要还有别的 Agent 在用，共用的文件就都保留。

## 进化模块（可选）

让 Sibyl 越用越懂你：记下你对每次预测的反应，算出它猜得准不准，在你要求时让 Agent 研究这些记录、写下心得，之后每次预测都带上这些心得。

它是单独安装的模块。基础功能装好之后，再对 Agent 说一句：

> Add the Sibyl evolution module to your Sibyl installation according to https://github.com/susyimes/sibyl/blob/main/evolve/SPEC.md

**记录什么**：每次 Sibyl 给出建议后，你的下一条消息会被归成四类之一：

| 类型 | 例子 |
|---|---|
| 采纳 | `s1`，或者把某条建议原样打了出来 |
| 采纳并补充 | `s2 顺便加上日志` |
| Agent 自己的方案 | `2` |
| 别的 | 你自己写的一句话（原样记下） |

每条记录还包括当时的几条建议和各自的确定性、Agent 那段话的结尾，以及当时用的是哪一版心得。

**新增的命令**

| 命令 | 作用 |
|---|---|
| `/predict stats` | 查看统计，不经过模型：命中率、首选命中率，以及确定性和实际采纳率是否一致（比如说 0.6 的建议实际只被选了 35%），还有每一版心得各自的命中率 |
| `/predict learn` | 让 Agent 研究记录，重写 `LEARNED.md`（命令在到达模型前就被拦下的环境，比如 Grok，会在你下一轮结束时进行） |
| `/predict forget` | 删掉全部记录和心得 |

**心得就是你的用户模型**：`LEARNED.md` 是几条关于你的要点，比如「这个用户提交前总会先说跑测试 (22/30)」「确定性 0.6–0.8 的建议实际只被选了 35%」。之后每次请 Agent 预测时，都会附在说明后面，作为参考，不是规则。
- **外壳固定，内容交给模型**。固定的只有四样：
  - 开头一行，写明第几版、日期、基于多少条记录；
  - 每条规律带上证据次数，少于 3 次的不写；
  - 校准数字照抄统计结果，不让模型自己估；
  - 不超过 1500 字，不写凭据和个人身份信息。

  分哪几节、写什么，由模型根据记录自己决定。学习说明里只是建议了几节：校准、你怎么说话、通常接下来说什么、什么不该建议、各项目的特点。
- **心得和你的设置分开**：`LEARNED.md` 归学习管，每次学习都可能重写，你也可以随时看、改或删；想永久保留的事写进你自己的 `PREDICT.md`，学习不会碰它。
- **所有 Agent 共用这一份**：Grok 学到的，Claude Code 预测时也会用上。统计会按 Agent 分开算，因为不同模型的确定性准不准，可能差别很大。

**隐私和开关**
- 记录会原样保存你说过的话，只存在本机的 `~/.sibyl/journal.jsonl` 里，不联网。
- 会话关着时什么都不记。
- `PREDICT.md` 里写 `journal: false` 就停止记录；`journal_max`（默认 2000）是最多保留的条数，超出时先删最旧的。
- 学习只在你说 `/predict learn` 时进行，写文件时照常需要你批准。

## 为什么这样设计

Sibyl 的前作是 [intent-predict](https://github.com/susyimes/intent-predict)，它从会话外面猜你的下一句。为此它需要：
- 好几家 Agent 的适配器、历史同步和会话绑定；
- 每轮额外调一次模型，要等十几到几十秒；
- 在另一个网页里显示建议，离你打字的地方很远。

其实 Agent 自己手里的信息最全，所以 Sibyl 让它自己观察自己，外面只留一个触发、一个开关和一份说明。

设计遵循 [AGENT.md](https://github.com/susyimes/agent-coding-principle/blob/main/AGENT.md) 的原则：
- 不限制模型的判断，预测什么由 Agent 决定；
- 规则少而松，只保留保护你的几条：只有你决定安装才会出现；随时能关、关了就完全不起作用；预测不等于你的同意；有外部影响的只列不做；自己接着做有步数上限；出错就正常结束；
- 限制都是显式的，可以关掉；
- 风险摆出来给你看，不藏起来。
