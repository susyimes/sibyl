# L1.5：由 Agent 自己当触发器

- **状态**：待讨论
- **提出**：2026-11-12
- **涉及**：基础规范 §2.2（分级）、§7（命令）、§9（安装与验收）、新增附录 B

## 背景

用户让 grok bot 照规范安装 Sibyl。它的环境没有一轮结束时的触发，只能装到 L1：把说明写进常驻简介，效果全靠 Agent 自觉，没有步数上限，也没有格式检查。

之后用户引导它换成了一版更严格的常驻说明，实际用下来可行。这一版的要点（据 grok bot 的回复整理）：

1. 每轮开头先读会话状态文件，读不到就当作关闭。
2. 开着时，每轮最后一条消息必须以 `Sibyl:` 建议块结尾；如果这一轮以选项卡结束，建议块放在它前面那条消息里。
3. 发出前按规范的格式自检一遍。
4. act 模式在状态文件里计步，到上限就停下来列建议；用户每发一条新消息，计数归零。
5. 推送、发送、删除、花钱、碰凭据这类事，只列出来，不替用户做。
6. 开关命令那一轮本身不做预测。
7. 旧版 L1 说明另存备份。

这说明：没有结束触发的环境，只要 Agent 能用工具读写持久的存储、能改自己的常驻说明，就能由它**自己扮演触发器**，做到比 L1 可靠得多。本方案把这种做法定为正式的一档，称为 L1.5。

## 定义

**L1.5 的前提**：环境没有 C1（一轮结束时能让 Agent 接着干的机制），但同时满足：
- Agent 能用自己的工具读写一份按会话的持久存储；
- Agent 能修改自己的常驻说明。

**L1.5 的做法**：由 Agent 按一段统一的常驻说明，在每轮里自己执行 L2 中 hook 负责的那部分逻辑：
1. **维护开关和计数**：用和 L2 同一个位置、同一种格式的状态文件。
2. **开着时，每轮最后一条消息以 `Sibyl:` 块结尾**，发出前按 §6 的格式自检。
3. **act 模式自己计步**：到 `max_auto_turns` 就停下来列建议；用户发一条新消息，计数清零。
4. **以界面组件结尾的轮次**（选项卡、按钮等），建议块放在最后一条文字消息里。
5. **安全规则不变**：有外部影响的只列不做；预测不等于用户的同意。

## 和 L1、L2 的对比

| | L1 | L1.5 | L2 |
|---|---|---|---|
| 谁来触发 | 靠 Agent 自觉 | Agent 照严格规则自己执行 | 环境的结束触发，有保证 |
| act 步数上限 | 没有 | 有，Agent 自己计数 | 有，由 hook 计数 |
| 格式自检 | 没有 | 有 | 由 hook 识别是否已给出建议 |
| 代价 | 常驻说明占一点上下文 | 开着时每轮多一两次读写状态的工具调用，常驻说明更长 | 几乎为零 |

## 安装流程：只能到 L1 时，提示用户可以升级

1. 安装时发现没有 C1，先照常装到 L1。
2. 检查 L1.5 的两个前提。两个都满足，就在安装报告末尾问用户，例如：

   > 这个环境没有结束时的触发，只能装到 L1。可以升到 L1.5：我每轮自己记录开关和计数、发出前检查格式，预测会更可靠，act 模式也有步数上限。代价是开着时每轮多一两次读写，回复稍慢。要升级吗？回复 `/predict level 1.5` 即可，以后也能用 `/predict level 1` 换回来。

3. **用户同意后**：
   - 把常驻说明换成规范里统一的 L1.5 说明段（附录 B）；
   - 备份原来的 L1 文本，记录改动；
   - 跑 L1.5 的验收（见下文）。
4. **用户不同意**：保持 L1。之后随时可以用 `/predict level 1.5` 升级，或用 `/predict level 1` 换回。

**为什么要先问**：L1.5 有用户应该知道的代价（每轮多一两次工具调用、常驻说明更长更严、回复稍慢）。按项目原则，升级和降级都应该是明确选择、可以撤销的。

**为什么用统一的说明段**：不让每个 Agent 各写一份，是为了让不同 Agent 在 L1.5 下表现一致，出了问题也能对照规范排查。grok bot 写的那版可以直接拿来当底稿。

## 一处收紧：关着时尽量不留痕迹

grok bot 现在是「每轮开头先读状态文件」，所以即使关着，每轮也要调一次工具，有延迟，也会出现在对话记录里。这不符合「关闭就是关闭」。建议改成：

- 只在会话的第一轮读一次状态，或者在不确定开关状态时再读，比如上下文被压缩之后；
- 其余时候，开关看对话里的 `/predict` 命令就知道了；
- 关着时不读也不写。

L1 和 L1.5 的说明都常驻在上下文里，所以要彻底不起作用，仍然只能用 `disable` 把说明撤掉。规范里要如实写明这一点。

## L1.5 的验收

1. 开启后，下一轮以 `Sibyl:` 建议块结尾，格式符合 §6。
2. 用户发一条新消息，计数清零；act 模式到上限就停下来列建议。
3. 关闭后不再出建议块，也不读写状态。
4. 以界面组件结尾的轮次，建议块出现在它前面那条文字消息里。
5. `disable` 之后，常驻说明和安装前的备份逐字一致。

这几条都要在真实对话里观察。L1.5 没有可以单独测试的 hook，参考核心的用例只能保证状态文件的格式和 L2 一致。

- **新增附录 B**：L1.5 的统一说明段，以 grok bot 那版为底稿，加上「关着时尽量不留痕迹」的收紧。
- **§9 安装**：

- **§7 命令**：新增 `/predict level 1|1.5`，用来在两档之间切换。
- **进化模块**：暂时仍要求 L2。以后可以考虑在 L1.5 下由 Agent 自己记录：它在下一轮本来就看得到用户的回复。
